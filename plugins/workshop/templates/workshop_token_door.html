{# The token door on the participant side of the login page (tokendoor.py `TokenDoor`, included by login.html through doors.py; PLAN.md §60). One box. What is typed in it is either the code on the slide, which makes an account, or the personal code somebody was given the first time, which opens theirs again. The page tells them apart; the participant does not have to know there are two kinds. Two states, and assets/door.js moves between them: entry the box, and the file control for somebody who kept their code as a file. Drawn by the server, so the page says something before the script runs. handout shown once, between "this code admits you" and "your account exists": the personal code, three ways to keep it, and a box to tick. The account is made only when Continue is pressed, so nobody owns an account whose code they were never shown. Everything the script says is here, in `data-*`, already translated. The script holds no sentence of its own: a string in a .js file never reaches the catalogue (CLAUDE.md, "Platform strings"). The nonce is the anonymous session's. The three requests this page makes are JSON, and core checks `CSRF-Token` on those whether or not anybody is signed in (CTFd/utils/initialization, `csrf`). `data-authed` is set when somebody is already signed in on this browser and opened the page anyway: the script then leaves their encryption key where it is, and clears it for everybody else. The QR library is loaded here and nowhere else: this is the only page that draws one. Without it (tools/build_vendor.sh not run) the script hides the figure and the other two ways still work. #}
