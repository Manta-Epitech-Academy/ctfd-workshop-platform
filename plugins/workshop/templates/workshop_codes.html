What a code does

  • It is typed by hand, so it is compared kindly. Case, spaces and dashes do not count, and neither does the letter O for a zero or I and L for a one. LILLE-2026 and lille 2026 are one code.
  • It is the cohort. Campus, event and date are what the supervision pages call the room; a code with neither event nor date is listed under the code itself.
  • It is closed, not deleted. Retired by hand, outside its window, or full: it admits nobody new and its accounts keep working. A cap counts every account the code ever made, banned ones included. Only a code nobody came in on can be deleted: the cohort is the code.
  • Ban shuts a cohort out and retires its code. Banned accounts cannot sign in and keep their progress, and the same button lets them back. Without retiring the code they would simply register again: an account here is nothing but a token. Deleting one account stays under Users. An account that has since become an admin or a supervisor is skipped.

What the door tells a stranger

  • One answer for every refusal, bar one. Unknown, retired, over, full: the same message, so the door cannot be used to learn which codes exist. The reason is in the registrations log.
  • A code that is not open yet says so. The door answers that the event has not started and when the code opens, so a room that is early does not go looking for another code. Anybody who types it learns that it exists: make a code later if that matters.
  • Wrong codes are counted, addresses are not. A text that is not a code stops being looked up after 10 tries in 15 minutes, and 300 wrong codes in one minute close the door to everybody until the minute is over.
  • That does not stop a patient guesser. A short word is found by a list in time. Use the random code, or give a word a window and a cap, when the instance holds something worth protecting.
