No code yet, so the route answers 404.

What the accounts are

  • Ordinary participants. No permissions, nothing a supervisor or an admin has. They appear on the scoreboard and in the counters like everybody else.
  • Verified on creation, because these instances send no mail and an unverified account could never do anything.
  • The code is stored on the account as the CTFd custom field External code: the account's own page shows it and an export carries it. The Users listing cannot search custom fields, which is why the accounts are listed above rather than linked to a filter that would not work.
  • Revoke bans, it does not delete. Banned accounts cannot sign in and keep their solves, and the button here undoes it. Deleting one account stays under Users, where the confirmation names the person. An account that has since become an admin or a supervisor is skipped.

How it stays hidden

  • Off, or with no code, the route answers 404 rather than a closed page: an instance not using this looks like one that never heard of it.
  • Ten wrong codes from one address stop it answering that address for fifteen minutes — also a 404, so running out of tries tells a prober nothing that "no such route" would not. A correct code clears the count, because a classroom is one address and somebody mistyping twice is not a prober.
  • It is independent of Registration Visibility, in both directions.
